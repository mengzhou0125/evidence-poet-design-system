# 学术图表类型分类与布局模板

论文中的图表类型有限且可归类。本文档为每种类型提供结构化的布局策略，避免每次从零开始排版。

生成 SVG 前，先判断原图属于哪种类型，再加载对应的布局模板。

---

## 类型判断决策树

```
原图有坐标轴（X/Y轴）？
  ├─ 是 → 有多条数据线/数据点？
  │       ├─ 是 → TYPE-B: Coordinate（坐标系图）
  │       └─ 否 → TYPE-B: Coordinate（单系列坐标图）
  └─ 否 → 元素之间有方向性箭头？
          ├─ 是 → 是否有分支/判断节点？
          │       ├─ 是 → TYPE-C: Flow（流程图）
          │       └─ 否 → 线性流向？
          │               ├─ 是 → TYPE-C: Flow（线性流程）
          │               └─ 否 → TYPE-E: Architecture（系统架构图）
          └─ 否 → 元素按行列排列成网格？
                  ├─ 是 → TYPE-A: Matrix（矩阵图）
                  └─ 否 → 元素有明确的层级/包含关系？
                          ├─ 是 → TYPE-D: Hierarchy（层级图）
                          └─ 否 → TYPE-F: Comparison（对比图）
```

## TYPE-A: Matrix（矩阵图）

**典型原图：** 二维分类框架、类型×级别矩阵、评估矩阵

**布局策略：**

```
方向：横向优先
画布参考宽度：700-800px
结构：列标题行 + 数据区域 + 映射区域

┌─────────────────────────────────────────────┐
│  [图表标题 — Playfair Display 15px]          │
├─────────────────────────────────────────────┤
│  Col-A      Col-B      Col-C      Col-D     │  ← 列标题（DM Mono 11px）
│ ┌────────┐┌────────┐┌────────┐┌────────┐   │
│ │        ││        ││        ││        │   │  ← 列区域（surface fill）
│ │        ││        ││        ││        │   │
│ └────────┘└────────┘└────────┘└────────┘   │
│  Y轴标签                                     │  ← 左侧纵轴（如有）
├─────────────────────────────────────────────┤  ← 分隔线
│  [项目映射说明 — foreignObject 自动换行]      │
├─────────────────────────────────────────────┤
│  Source: Author et al. (Year), Fig. N        │
└─────────────────────────────────────────────┘
```

**关键规则：**
- 列间距 = 列宽 × 0 （列之间无间距，用 border 分隔）或 列宽 × 10-15%（有间距）
- 如有纵轴，纵轴标签用 `<g transform="rotate(-90)">` 旋转
- 如有数据线穿越列（如 Parasuraman fig2），数据点用 `<circle r="3">` 标记
- 数据线之间用实线 vs 虚线区分，不用颜色区分（Monochrome 兼容）
- 列标题使用 DM Mono 等宽字体，保持技术标签感

**参考输出：** `paper_parasuraman_2000_fig2.svg`（Types and Levels of Automation）

## TYPE-B: Coordinate（坐标系图）

**典型原图：** 散点图、折线图、二维空间定位图、光谱/连续体图

**布局策略：**

```
方向：横向
画布参考宽度：650-750px
结构：标题 + 坐标区域 + 映射区域

┌─────────────────────────────────────────┐
│  [图表标题]                              │
├─────────────────────────────────────────┤
│ Y轴  ┌──────────────────────────┐       │
│ 标签 │                          │       │
│  ↑   │    ·A          ·B       │       │
│  |   │         ·C              │       │
│  |   │                    ·D   │       │
│      └──────────────────────────┘       │
│           X轴标签 →                      │
├─────────────────────────────────────────┤
│  [项目映射]                              │
├─────────────────────────────────────────┤
│  Source: ...                             │
└─────────────────────────────────────────┘
```

**关键规则：**
- 坐标轴用 1.5px `--text-primary` 实线，轴末端可加箭头
- 轴标签用 DM Mono 11px
- 数据点用 `<circle>` 标记，旁边附标签用 Plus Jakarta Sans 10px
- 如果原图是连续光谱（如 "低→高"），用等间距的灰度色块阶梯（3-5 级，从 `--surface` 到 `--border` 色）+ 标记点表示，不使用 `<linearGradient>`
- 项目映射标注用虚线框标记在坐标空间内的位置

## TYPE-C: Flow（流程图）

**典型原图：** 决策流程、迭代框架、方法论步骤、评估流程

**布局策略：**

```
方向：纵向优先
画布参考宽度：500-600px
结构：标题 + 流程节点链 + 映射区域

┌────────────────────────────────┐
│  [图表标题]                     │
├────────────────────────────────┤
│      ┌──────────────┐          │
│      │   Step 1      │          │
│      └──────┬───────┘          │
│             │ ↓                 │
│      ┌──────┴───────┐          │
│      │   Step 2      │          │
│      └──────┬───────┘          │
│             │                   │
│    ┌────────┼────────┐         │  ← 分叉（树形连接线规则）
│    ↓        ↓        ↓         │
│  ┌───┐  ┌───┐  ┌───┐         │
│  │ A │  │ B │  │ C │         │
│  └───┘  └───┘  └───┘         │
│    └────────┼────────┘         │  ← 汇聚
│             ↓                   │
│      ┌──────────────┐          │
│      │   Step 3      │          │
│      └──────────────┘          │
├────────────────────────────────┤
│  Source: ...                    │
└────────────────────────────────┘
```

**关键规则：**
- 节点之间垂直间距 15-20px（箭头线段长度）
- 分叉点使用树形连接线规则（见 svg-spec.md）
- 虚线框（dashed stroke）用于"评估标准"等非实体步骤
- 反馈/迭代循环用虚线弧线 + `--text-muted` 色箭头，从下方绕回上方
- 节点宽度统一（同层级节点等宽）
- 侧边注释（如"Low→High"标注）用 DM Mono 10px `--text-muted` 色

**参考输出：** `paper_parasuraman_2000_fig3.svg`（Iterative Framework）

## TYPE-D: Hierarchy（层级图）

**典型原图：** 分类体系、概念层级、组织结构、自动化级别

**布局策略：**

```
方向：纵向（自上而下）或横向（自左而右）
画布参考宽度：纵向 500-600px，横向 700-800px

纵向布局：
┌────────────────────────────────┐
│  [图表标题]                     │
├────────────────────────────────┤
│         ┌─────────┐            │
│         │ Root    │            │
│         └────┬────┘            │
│         ┌────┼────┐            │  ← 树形分叉
│      ┌──┴──┐  ┌──┴──┐         │
│      │ L1-A│  │ L1-B│         │
│      └──┬──┘  └──┬──┘         │
│      ┌──┼──┐  ┌──┼──┐         │
│     [L2] [L2] [L2] [L2]       │
├────────────────────────────────┤
│  Source: ...                    │
└────────────────────────────────┘
```

**关键规则：**
- 同层级节点水平等间距排列
- 层级之间垂直间距 40-60px
- 树形连接线遵循分叉规则（不直接从父节点拉多条线）
- 叶节点可以用更轻的视觉权重（更细边框、更浅文字）
- 如果层级超过 4 层，考虑横向布局以节省纵向空间

## TYPE-E: Architecture（系统架构图）

**典型原图：** 系统模块关系图、信息处理模型、多层架构

**布局策略：**

```
方向：横向（左到右）为主流
画布参考宽度：800-1000px
结构：水平层或模块 + 连接箭头

┌──────────────────────────────────────────────────┐
│  [图表标题]                                       │
├──────────────────────────────────────────────────┤
│  ┌────────┐    ┌────────┐    ┌────────┐    ┌────────┐ │
│  │Module A │───→│Module B │───→│Module C │───→│Module D │ │
│  └────────┘    └────────┘    └────────┘    └────────┘ │
│       ↑                            │                   │
│       └────────────────────────────┘                   │
│                  (feedback loop)                        │
├──────────────────────────────────────────────────┤
│  [项目映射]                                       │
├──────────────────────────────────────────────────┤
│  Source: ...                                      │
└──────────────────────────────────────────────────┘
```

**关键规则：**
- 模块之间水平间距 60-80px（箭头需要空间放标签）
- 箭头标签用 Plus Jakarta Sans 10px，置于箭头中点上方 5px
- 如果有反馈循环，用虚线弧线绕过主流程
- 每个模块内部可包含子文字说明（11px `--text-body`）
- 如果模块数量 >6，考虑分两行排列或使用分组框

**参考输出：** `paper_parasuraman_2000_fig1.svg`（Four-Stage Model）

## TYPE-F: Comparison（对比图）

**典型原图：** 方法对比、条件对比、before/after、并列框架

**布局策略：**

```
方向：横向并列
画布参考宽度：700-800px

┌──────────────────────────────────────────┐
│  [图表标题]                               │
├──────────────────────────────────────────┤
│  ┌──────────────┐  ┌──────────────┐      │
│  │ Approach A    │  │ Approach B    │      │
│  ├──────────────┤  ├──────────────┤      │
│  │ Feature 1: X │  │ Feature 1: Y │      │
│  │ Feature 2: X │  │ Feature 2: Y │      │
│  │ Feature 3: X │  │ Feature 3: Y │      │
│  └──────────────┘  └──────────────┘      │
├──────────────────────────────────────────┤
│  Source: ...                              │
└──────────────────────────────────────────┘
```

**关键规则：**
- 并列元素必须等宽、等高（视觉上绝对对称）
- 共享特征的行必须水平对齐
- 如果对比维度 >2，使用列式布局（类似 Matrix）
- 用 DM Mono 标签区分对比对象名称

## 通用简化原则

无论哪种图表类型，简化重绘时遵循以下原则：

1. **保留结构，去除装饰：** 原图的核心逻辑关系必须完整保留，但所有装饰性元素（阴影、渐变、3D 效果、图标、照片）一律去除
2. **文字标签全部英文：** 因为用户需要在英文作品集中引用
3. **信息密度优先：** 宁可紧凑也不留无用空白——"学术期刊插图"的密度感
4. **统一视觉权重：** 同层级的节点必须使用相同的大小、字体、颜色
5. **一个维度一种区分方式：** 不要同时用颜色+形状+大小来区分同一个维度，选择一种即可
